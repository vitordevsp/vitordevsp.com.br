# Legacy: Build Changelog

## Purpose

Preserve the useful approach for turning implementation history into a human-readable changelog.

## Useful legacy guidance

- Use recent git history and finished work scopes to draft changelog entries.
- Group by real topic/impact, not by raw commit order.
- Avoid copying every commit line; summarize what matters.
- If version classification is uncertain, state the uncertainty explicitly.

## Current Agents Studio interpretation

- Changelog updates should be coordinated with commit boundaries and semantic versioning.
- Prefer small, reviewable changes and explicit validations.
