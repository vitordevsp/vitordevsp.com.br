## Contexto

Depois que vídeos, projetos e home estiverem na lib moderna, o legacy deve ser removido para evitar manutenção duplicada. A remoção só é segura se as validações externas confirmarem que as rotas antigas não são consumidas.

## Objetivo

Remover os recursos legacy do Notion e atualizar documentação/variáveis para refletir a integração moderna como única base operacional.

## Escopo

### Fazer

- Remover imports internos restantes de `src/app/api/notion/_resources/`.
- Remover arquivos legacy quando não houver consumidor externo.
- Atualizar `.env.example` para remover `NOTION_KEY` se ela não for mais usada.
- Atualizar `docs/product/notion/` com o estado pós-migração.

### Não fazer

- Não remover rotas públicas se `P001-T001` indicar consumidor externo.
- Não apagar documentação histórica útil sem migrar o conhecimento para o local correto.
- Não alterar o design das páginas migradas.

## Detalhes técnicos

Depende de: `P001-T003`, `P001-T004` e da resposta de consumidores externos em `P001-T001`.

Se houver consumidor externo, manter as rotas antigas temporariamente ou criar uma camada de compatibilidade em vez de remover tudo na mesma mudança.

## Critérios de aceite

- [ ] Não há import interno para `_resources/` após a limpeza.
- [ ] Variáveis legacy foram removidas ou marcadas como compatibilidade temporária.
- [ ] Docs de Notion descrevem a lib moderna como caminho principal.
- [ ] Qualquer exceção de compatibilidade está registrada.
