## O que fazer

Alterar `src/lib/notion/client.ts` para passar `notionVersion` explicita ao construtor do `Client`:

```ts
import { Client } from "@notionhq/client"

export const notion = new Client({
  auth: process.env.NOTION_TOKEN,
  notionVersion: "2026-03-11",
})
```

Registrar a versao escolhida em comentario curto apontando para o motivo da escolha.

## Por que

Hoje a lib nao fixa `Notion-Version` e herda o default do SDK, que muda a cada major do `@notionhq/client`. Um `pnpm update` pode mudar o contrato silenciosamente (ex.: mudar shape de `databases.query`).

`Notion-Version` e header **obrigatorio** na REST API. O SDK injeta um default, mas esse default e um alvo movel.

## Qual versao escolher

- `2026-03-11` e a latest (ver [reference/versioning.md](../../../resources/notion-docs/reference/versioning.md)).
- `2025-09-03` introduziu `data_sources` (ver P002-T007).
- Escolher `2026-03-11` da acesso a tudo; escolher algo mais antigo so se houver regressao conhecida.

Confirmar que o `@notionhq/client` instalado (ver `package.json`) suporta a versao escolhida — ver [compatibility table](https://github.com/makenotion/notion-sdk-js?tab=readme-ov-file#requirements-and-compatibility) do SDK.

## Como validar

- `pnpm build` passa.
- `/posts`, `/posts/[slug]`, `/projetos`, `/videos` continuam carregando em dev.

## Nao fazer

- Nao subir versao so para alinhar com a doc se quebrar rotas atuais — reverter e abrir nova task com o ajuste.
