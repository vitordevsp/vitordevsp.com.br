## Contexto

O SDK do Notion mistura respostas completas e parciais. Alguns casts locais ajudam a manter o código legível, mas casts amplos demais escondem inconsistências e dificultam evolução dos domínios.

## Objetivo

Revisar os wrappers de database e page para reduzir casts inseguros onde houver alternativa clara, mantendo uma API local honesta e compreensível.

## Escopo

### Fazer

- Revisar `src/lib/notion/features/databases/index.ts`.
- Revisar `src/lib/notion/features/pages/index.ts`.
- Trocar casts amplos por tipos auxiliares ou guards quando isso melhorar segurança.
- Manter casts localizados quando o SDK não permitir tipagem limpa.

### Não fazer

- Não criar uma abstração maior que o problema.
- Não refatorar toda a DSL de filtros.
- Não bloquear `P002-T007` se o endpoint novo resolver parte dos casts.

## Detalhes técnicos

Depende de: `P001-T002`.

O critério não é zerar casts, mas deixar explícito onde o wrapper assume um contrato que o SDK não expressa bem.

## Critérios de aceite

- [ ] Casts principais dos wrappers foram revisados.
- [ ] Casts mantidos têm escopo pequeno e motivo claro.
- [ ] Tipos públicos da lib continuam legíveis.
- [ ] Callers existentes não precisam conhecer detalhes do SDK.
