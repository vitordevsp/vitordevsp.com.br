## Contexto

`getAllBlockChildren` é ponto sensível porque alimenta a página de leitura. O modo `deep: true` busca blocos aninhados um por vez, mas trocar por `Promise.all` sem limite pode cruzar o rate limit do Notion em páginas com muitos toggles/listas.

## Objetivo

Melhorar a busca recursiva de blocos com concorrência limitada e tipar `__children` sem mudar a assinatura pública da função.

## Escopo

### Fazer

- Criar tipo explícito para blocos com `__children`.
- Remover atribuição via `(parent as any).__children`.
- Trocar loop sequencial por concorrência limitada.
- Tratar 429 respeitando `Retry-After` ou, no mínimo, evitando crash opaco.
- Documentar o contrato de paginação do wrapper.

### Não fazer

- Não introduzir lib nova sem necessidade clara; um limitador pequeno local é suficiente.
- Não mudar a assinatura pública de `getAllBlockChildren`.
- Não mudar o shape consumido pelo `PageRenderer`.

## Detalhes técnicos

Tipo esperado em `src/lib/notion/features/blocks/types.ts`:

```ts
export type AnyNotionBlockWithChildren = AnyNotionBlock & {
  __children?: AnyNotionBlock[]
}
```

O rate limit oficial é 3 req/s em média, com bursts. 429 retorna `Retry-After` em segundos.

## Critérios de aceite

- [ ] `__children` é tipado sem `as any` no ponto principal de atribuição.
- [ ] Busca profunda usa limite de concorrência.
- [ ] 429 tem tratamento explícito.
- [ ] Paginação (`start_cursor`, `has_more`, `next_cursor`, default 10, max 100) está documentada no wrapper.
- [ ] `PageRenderer` continua recebendo o mesmo shape.
