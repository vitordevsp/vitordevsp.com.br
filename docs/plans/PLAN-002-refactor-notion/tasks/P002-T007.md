## Contexto

A partir da versão `2025-09-03`, databases passaram a expor data sources e o endpoint canônico virou `POST /v1/data_sources/{id}/query`. O wrapper moderno deve acompanhar esse contrato para evitar ficar preso a caminho legado da API.

## Objetivo

Migrar `getDatabaseItems` para usar `data_sources.query` mantendo o contrato local usado pelas pages e domínios.

## Escopo

### Fazer

- Revisar o wrapper em `src/lib/notion/features/databases/index.ts`.
- Usar o endpoint canônico de data source quando suportado pelo SDK.
- Preservar filtros, sorts, paginação e tipo de retorno local.
- Atualizar nomes internos se `databaseId` na prática passar a ser `dataSourceId`.

### Não fazer

- Não quebrar callers com uma renomeação pública precipitada.
- Não migrar schema do Notion.
- Não fazer refactor de domínios nesta tarefa.

## Detalhes técnicos

Depende de: `P002-T006`.

Se a mudança exigir distinguir database ID público de `data_source_id` interno, registrar a decisão antes de propagar para domínios.

## Critérios de aceite

- [ ] Wrapper usa `data_sources.query` ou equivalente suportado pelo SDK instalado.
- [ ] Callers existentes continuam com contrato claro.
- [ ] Filtros, sorts e paginação continuam funcionando.
- [ ] Dependências de versão da API estão documentadas.
